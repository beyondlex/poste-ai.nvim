# Code Review — 2026-09-06

Full review of `lua/poste-ai/` + `plugin/` (streaming/chat/window core reviewed
hardest), followed by surgical bug fixes, regression tests, and smell
documentation. No large refactors. No real network calls — all provider I/O in
tests goes through the mock adapter fixtures or the local `real_stream_spec`
Python SSE server.

## Bugs fixed

1. **Single-line range mentions silently dropped**
   `lua/poste-ai/chat/mention.lua:19-26` (root cause) — `range_mention`
   (`mention.lua:187`) emits `@path(10)` for a one-line visual selection, but
   `file_ref` only parsed the `@path(l1-l2)` form. The `path(10)` token fell
   through to a literal file lookup, failed `fs_stat`, and the ref was dropped:
   the LLM never saw the mentioned line, with no error anywhere.
   Fix: also match `^(.+)%((%d+)%)$` with `l2 = l1`.
   Tests: `tests/ai/mention_spec.lua` — parse + resolve single-line refs.

2. **Concurrent-send race during async composition**
   `lua/poste-ai/chat/stream.lua:140,165-173` — `st.busy` is only set inside
   the compose callback, after async mention resolution / `auto_context` (up to
   the 10s guards). A second `send` in that window passed the busy gate; the
   two composes raced on `st.current`/`st.seq`, the loser's callbacks were
   dropped by the epoch guard, stranding an empty assistant placeholder and an
   in-flight (never cancelled) curl job. Fix: a `st.pending` flag held from
   send validation until the stream takes over (or finalize cleans up), plus an
   epoch check so a `force_reset` during composition drops the stale compose.
   Test: `tests/ai/stream_spec.lua` — "rejects a send while an async compose is
   still pending".

3. **`finalize` could crash and wedge `busy` forever**
   `lua/poste-ai/chat/stream.lua:112-115` — `finalize` synthesizes
   `st.current` when missing but then unconditionally indexed
   `st.current.session_msg`; a nil `session_msg` would throw mid-finalize,
   after which `st.busy` is never cleared — the exact wedge AGENTS.md warns
   about. Now all `session_msg` writes are guarded.
   Test: `tests/ai/stream_spec.lua` — "finalize survives a missing session_msg
   without wedging busy" (drives `_test.finalize` directly).

4. **Dead handle re-attached after a synchronous adapter error**
   `lua/poste-ai/chat/stream.lua:239-243` — when an adapter's `stream()` calls
   `on_error` synchronously, finalize has already cleared `busy`/`handle`, but
   `M.send` then unconditionally did `st.handle = handle`, dirtying the just
   cleaned state (and `handle.cancel` may not even exist, see 5).
   Test: `tests/ai/stream_spec.lua` — "leaves no stale handle when the adapter
   errors synchronously".

5. **openai handle returned without `cancel()` on jobstart failure**
   `lua/poste-ai/provider/openai.lua:143-150` — `handle.cancel` was defined
   after the `jobstart`-failure early return, so that path returned a handle
   with no `cancel` method. Now defined up front (a no-op while `job_id` is
   nil). No direct unit test (forcing a synchronous `jobstart` failure isn't
   deterministic headlessly); fixed defensively, covered indirectly by the
   stream lifecycle tests.

6. **Unbounded treesitter spec cache during streaming**
   `lua/poste-ai/chat/tshl.lua:29-32,55-60` — specs are cached per
   `(lang, full block text)`; streaming re-renders the growing block once per
   flush tick, so one long code block cached a full copy of every intermediate
   text until nvim exited. Fix: evict-all at a 256-entry cap (keeps cross-turn
   reuse, bounds memory). Test: `tests/ai/tshl_spec.lua` — cache stays bounded
   past the cap.

7. **Slash palette keymaps hijack the input after chat teardown**
   `lua/poste-ai/chat/window.lua:76-81,204,318` and
   `lua/poste-ai/chat/popup.lua:72-83,102-109` — closing the chat while the
   palette was up killed the floating window (anchor gone) without ever running
   `popup.close()`, leaving the temporary insert-mode keymaps installed on the
   (reused) input buffer. After a reopen, Enter/Up/Down drove the dead palette;
   Enter could execute a stale slash command such as `/new` (wiping the
   session). Fix: window teardown (both `M.close` and the WinClosed path) closes
   the popup explicitly, and popup handlers drop the keypress and restore maps
   when the popup window is already gone.
   Test: `tests/ai/popup_spec.lua` — teardown closes the popup, restores
   keymaps, and a dead popup drops the next key instead of firing callbacks.

## Bugs found, not fixed (with rationale)

- **Error/note blocks are not persisted** — `conversation.append_error` /
  `append_note` write to the buffer only; `session.messages` keeps the
  assistant message with an `errored` flag but never the error text, and
  `commands.open_chat` re-renders from the session on every open, so error and
  cancelled notes vanish on reopen/toggle. Fixing properly means persisting
  `error`/`note` records (a persistence-format change felt too large for this
  pass); documented as a known limitation.
- **Session switch mid-stream writes into the stale session** — `finalize`
  updates `st.current.session_msg` (old session) but saves
  `session.current()` (new session); the old session's final text persists only
  if it becomes current again. Narrow edge case; a real fix belongs to the
  single-source-of-truth refactor below.
- **`M.open` partial-failure cleanup** — if the first `vim.cmd(vsplit)` errors,
  `st.conv_win` is left set with no input pane; `is_open()` masks it and a
  stale window may remain. Low likelihood (fixed geometry), left as-is.
- **Ranged file ref past EOF** (`mention.resolve_ref`) — `@file(9999-9999)` on
  a short file clamps to an empty fenced block with a "(lines 9999-9999)"
  header. Cosmetic; a clear "range out of bounds" note would be nicer.
- **Session id collision** — `make_id` is second-resolution timestamp + 4-digit
  random; two sessions created in the same second can overwrite each other.
  Probability low, impact low (one lost session), left as-is.

## Smells identified (suggested remediation — not applied)

- **Two sources of truth for messages** — `conversation.st.messages` mirrors
  `session.current().messages` on every turn, and the two can drift (see the
  mid-stream switch case above). Suggested: make the session the single owner
  and treat the conversation buffer as a view with a dirty-flag re-render.
- **O(n²) mark application** — `conversation.apply_marks` finds each message's
  row anchor by identity-scanning `st.messages` (O(n) per message), so
  `set_messages` / `redraw_marks` (run on every `WinResized`) are quadratic for
  long sessions. Suggested: pass the row anchor into `apply_marks` directly.
- **Deprecated option APIs in popup.lua** — `nvim_buf_set_option` /
  `nvim_win_set_option` (deprecated since 0.10, removal planned) while the rest
  of the codebase uses `nvim_set_option_value`. Mechanical migration.
- **Duplicated `truncate` helpers** — `conversation.lua:325-334` and
  `outline.lua:32-41` are byte-for-byte duplicates. Suggested: one shared
  helper module.
- **API key in curl argv** — `openai.build_request` passes
  `Authorization: Bearer <key>` as an argument, visible in `ps` to other local
  users. The key is never logged (verified: `log.request`/`log.response` carry
  no credentials). Suggested: pass the header via stdin (`--header @-`) or a
  0600 temp file. Common upstream tradeoff; needs a small transport change.
- **`commands.open_chat` re-renders the session on every invocation** —
  including `:PosteAIChat <ctx>` while already open, discarding any
  conversation-only blocks (see unpersisted notes above).
