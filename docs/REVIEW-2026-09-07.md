# Code Review — 2026-09-07

Follow-up to `REVIEW-2026-09-06.md`. Baseline: the 19 spec files were green
after the previous pass. This pass re-read every module under `lua/poste-ai/`,
fixed the newly found bugs plus three of the previous report's recorded smells,
and resolved the biggest "found, not fixed" item.

## Fixed this round

1. **`at_bottom` read the wrong buffer** (`chat/window.lua`) — `line("$")`
   without a win argument evaluates the *current* window's buffer. Scrolling
   the conversation pane while another window was focused compared tail-follow
   against the wrong file. Both `line()` calls now pass `win`.
   Test: window_spec "reports at_bottom correctly" now focuses a tall foreign
   window before asserting.

2. **Final reply stranded on mid-stream session switch** (`chat/stream.lua`) —
   `finalize` wrote the assistant text onto the session the stream started in,
   but saved `session.current()` (the *new* session). `st.current` now carries
   the owning session and finalize persists that one.
   Test: stream_spec "finalize saves the session the stream started in…".

3. **Error/note blocks were not persisted** (the previous report's #1 "found,
   not fixed") — `session.append_record(role, text, s?)` stores error/note
   records in the message list; `finalize` (error + cancel) and the code-block
   executor write through it. `history_messages` ignores the new roles, so the
   LLM-visible history is unchanged; rendering already supported both roles,
   so reopen/toggle now reproduces them.
   Tests: stream_spec "re-renders persisted error and note blocks…", plus
   updated assertions in the cancel/error tests.

4. **Session id collision window widened** (`chat/session.lua`) — the random
   tail went from 4 digits to 6 hex chars, so two sessions created in the same
   second no longer overwrite each other's files.

5. **Docstring drift** (`provider/registry.lua`) — `get()` never consults the
   provider name (it isn't available on cfg); the docstring said it did.

## Smells cleared (from the 2026-09-06 list)

- Deprecated `nvim_buf_set_option` / `nvim_win_set_option` in `chat/popup.lua`
  → `nvim_set_option_value`.
- Duplicated `truncate` helper → new `lua/poste-ai/text.lua`; `outline._truncate`
  stays as a `_test`-visible alias.
- O(n²) `apply_marks` → takes the row anchor directly; full re-renders
  (`set_messages`, `redraw_marks` on WinResized) are linear again.

## Found, not fixed (with rationale)

- **API key in curl argv** (`provider/openai.lua`) — unchanged from the
  previous report. `--header @-` conflicts with `--data-binary @-` (both want
  stdin); a 0600 temp file needs lifecycle handling on every exit path.
  Deliberately deferred; the key is never logged (re-verified).
- **`M.open` partial-failure cleanup** — unchanged, fixed geometry.
- **Ranged file ref past EOF** — the header now shows the *clamped* range
  (`(lines 9999-100)`); still cosmetic.
- **`commands.open_chat` re-renders on every invocation** — impact is now
  minimal after fix 3 (error/note blocks survive), so the remaining cost is a
  redundant render, not data loss.
- **`auto_context`/mention compose window**: `M.cancel()` clear
  `st.pending` — by design, the 10 s guards guarantee compose always runs.
